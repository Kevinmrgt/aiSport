# C4.3.3 — Modèle de cas support GitHub

> **État par défaut : SIMULATION.** Ce document ne correspond pas à un retour
> réel et ne doit pas être présenté comme tel. Si un retour réel est disponible,
> le remplacer par sa trace vérifiable, retirer la mention `SIMULATION` et ne
> conserver aucune donnée personnelle.

Ce modèle reprend tous les champs du formulaire GitHub
[`support_case.yml`](../../../.github/ISSUE_TEMPLATE/support_case.yml). Il est
conçu pour être copié dans une issue créée depuis le modèle **Cas support client Bloc
4**. Aucun ticket n'est créé par ce document.

---

## Métadonnées GitHub

| Champ                             | Valeur à saisir                                           |
| --------------------------------- | --------------------------------------------------------- |
| Titre de la simulation            | `[SUPPORT][SIMULATION] [À compléter : situation fictive]` |
| Labels proposés par le formulaire | `rncp:bloc4`, `type:support`, `status:triage`             |
| Statut de la preuve               | `Simulation — aucun retour réel n'est affirmé`            |
| URL de l'issue                    | `[À compléter : URL après création uniquement]`           |

## Formulation de transparence à conserver pour une simulation

```text
SIMULATION — Cas construit pour illustrer le traitement support C4.3.3.
Il ne provient pas d'un retour client réel et ne démontre pas une validation
par un utilisateur réel.
```

## Checklist avant dépôt

- [ ] La mention `SIMULATION` apparaît dans le titre et le contexte tant qu'aucun retour réel n'est produit.
- [ ] Aucun nom, courriel, identifiant de compte, donnée de santé ou autre donnée personnelle n'est inclus.
- [ ] Toute action effectivement réalisée est séparée des actions seulement envisagées.
- [ ] Les références à un ticket, une PR, une version ou un changelog ne sont ajoutées qu'après leur création.
